这份文档是当前 MiniOneRec 后续研究的持续更新日志，不是正式论文草稿。它的主要目标有四个：

\begin{itemize}
  \item 持续同步当前研究主线与最新实验结论；
  \item 记录每一轮实验实际做了什么、改了什么；
  \item 区分已经比较稳定的事实和仍然开放的想法；
  \item 为后续正式写论文保留一条清晰、可回溯的叙事链条。
\end{itemize}

\section{当前研究状态}

\subsection{当前方向}

当前研究方向可以概括为：

\begin{quote}
用图结构作为协同信息的载体，并以层级感知的方式，把 graph-structured collaborative information 融合进 MiniOneRec 的语义 SID 构建过程。
\end{quote}

这里的重点不是比较哪一种 graph encoder 更强，而是回答三个核心问题：

\begin{enumerate}
  \item 什么样的图适合承载协同信息？
  \item 图结构协同信息应该怎样在不同 SID level 上体现层级感知？
  \item 图协同信息应该如何进入 MiniOneRec 的纯语义 SID，而不破坏语义 backbone 的稳定性？
\end{enumerate}

\subsection{为什么转向这个方向}

当前方向主要来自以下几条逐步稳定下来的观察：

\begin{itemize}
  \item SID collision 存在，但看起来不是主矛盾；
  \item 当前 SID 主要由文本语义驱动，缺少直接协同约束；
  \item 大量错误表现为“prefix 对了，但 leaf 错了”，说明 local leaf ambiguity 更像核心瓶颈；
  \item 早期 naive front-end collaborative fusion 不但没有稳定提升，反而可能破坏量化结构。
\end{itemize}

\section{当前较稳定的事实}

到目前为止，以下结论已经足够稳定，可以继续指导方法设计：

\begin{enumerate}
  \item \textbf{局部歧义是真问题。} 模型在进入正确语义区域后，最后一层 leaf 仍然经常选错。
  \item \textbf{图协同信号是有用的。} 即使还没有改训练版 SID，graph-structured collaborative signal 已经能在 top-1 SID error 上提供额外判别力。
  \item \textbf{中尺度图视图很重要。} 最有价值的协同视图既不是纯 global，也不是纯 last-step local。
  \item \textbf{轻量净化是必要的。} raw collaborative graph 往往弱于 purified graph。
  \item \textbf{论文启发的频域中尺度图比第一版 heuristic middle-view 更强。}
  \item \textbf{当前仓库默认的 \texttt{sid-train} 超参数与上游 MiniOneRec 不一致。} 真正能复现低 collision SID 的，是 upstream-style 的 \texttt{RQ-VAE} 训练制度，而不是当前默认的 \texttt{epochs=10, batch\_size=256}。
  \item \textbf{不能只看 \texttt{sid-train} collision。} 最终真正有意义的是 \texttt{sid-generate} 后的 \texttt{index.json} collision；train-stage 排名和 final index 排名可能并不一致。
  \item \textbf{Hierarchy-aware graph regularization 已经在 final SID 上给出正信号。} 在 upstream-aligned regime 下，Industrial 上 \texttt{hierarchy\_reg} 的 final generated SID collision 低于强语义 baseline。
  \item \textbf{这种 tokenizer 改进已经部分传到 SFT。} 当前 hierarchy 版本在 Industrial 上提升了 \(\mathrm{NDCG}@3\) 和 \(\mathrm{HR}@3\)，但还没有形成全面的 \( @10+ \) 优势。
  \item \textbf{下游收益主要集中在 crowded local ambiguity。} evaluate 诊断表明，hierarchy 主要修复的是 same-\(l_2\) 与高 fanout 目标上的局部错误，而不是一个均匀的全局收益。
  \item \textbf{当前的 \texttt{mgr\_upstream\_baseline} 应被视为 internal control，而不是主 baseline。} 真正需要锚定的主 baseline 应该是原版 MiniOneRec 的 recipe-aligned 结果，以及最强的原版 MiniOneRec SFT / RL 结果。
  \item \textbf{ambiguity-aware tokenizer v2 已经在原版 MiniOneRec 上给出 recipe-sensitive 的下游正信号。} 当前最优的 \texttt{v2} 下游 recipe 不是 \texttt{title\_history2sid\_on + desc\_align\_off}，而是 \texttt{title\_history2sid\_on + desc\_align\_p05}；在这条 recipe 上，\texttt{v2} 相对原版 MiniOneRec 的同配方版本在 \(\mathrm{NDCG}@1/3/5/10\) 和 \(\mathrm{HR}@1/3/5\) 上都更好。
  \item \textbf{当前 v2 还没有超过最强原版 MiniOneRec recipe，但差距已经很小。} Industrial 上最强原版 MiniOneRec SFT 仍是 \texttt{title\_history2sid\_off + desc\_align\_p05}；当前最优 \texttt{v2\_on\_p05} 与其相比，\(\mathrm{NDCG}@10\) 只差约 \(0.0010\)，\(\mathrm{HR}@10\) 只差约 \(0.0046\)。
  \item \textbf{strongest-recipe 失配的主因已经拆清。} 当前 strongest original MiniOneRec recipe 与 \texttt{v2} 的主要冲突不是 \texttt{desc\_align\_p05}，而是 \texttt{title\_history2sid\_off}；在 \texttt{title\_history2sid\_on} 保持开启时，\texttt{desc\_align\_p05} 对 \texttt{v2} 是净正增益。
  \item \textbf{stage-2 第一轮 retention-targeted tokenizer refinement 已完成首轮筛选。} \texttt{R202a}（\texttt{stop-gradient} hierarchy isolation）是当前唯一在 retention-oriented 结构指标上给出干净正信号的分支；\texttt{R202b-r075} 与 \texttt{R205} 虽然都把 final generated collision 从 \(13/3686\) 压到 \(12/3686\)，但都显著恶化了 local ambiguity structure。
  \item \textbf{当前没有任何 stage-2 分支在下游超过 \texttt{v2\_on\_p05} 主线。} \texttt{R208}（\texttt{R202a -> SFT/evaluate}）已经完成，但 \(\mathrm{NDCG}@10\) 与 \(\mathrm{HR}@10\) 都低于当前最佳 \texttt{v2\_on\_p05}；因此当前最强 end-to-end 主线仍然是 \texttt{v2\_on\_p05 -> RL}。
\end{enumerate}

\section{被削弱或阶段性放下的方向}

\subsection{Naive 前端协同融合}

之前的实验说明，粗糙的前端语义加协同融合会破坏 SID 结构并伤害量化稳定性。这并不意味着所有前端协同融合都是错的，只是否掉了那一版过于粗糙的融合方式。

\subsection{把后验局部修正当成最终论文主线}

局部后验修正仍然是很有用的诊断工具和原型验证工具，但单独作为最终论文主方法太弱。更有价值的主线，还是把图结构协同信息以层级感知方式写回 SID 构建本身。

\section{实验时间线}

\subsection{阶段 0：问题收敛}

这一阶段的主要贡献还是概念层面的。项目从一个较宽泛的“往 SID 里加协同信息”方向，逐渐收敛到更明确的表述：

\begin{quote}
图结构承载的协同信息，应该以层级感知且保结构的方式进入 SID 构建。
\end{quote}

这一阶段同时也固定了三个核心问题，并明确了图在当前研究中的身份：

\begin{quote}
图不是主要比较对象，而是 collaborative information 的结构化载体。
\end{quote}

\subsection{阶段 1：初始 Graph-Bank Probe（2026-04-09）}

\subsubsection*{做了什么}

我们新增了一套独立 probe，不修改 MiniOneRec 原有训练或评测主链，只在已有 top-1 SID 错误样本上测试不同 graph view 的判别能力。测试的视图包括：

\begin{itemize}
  \item coarse collaborative graph；
  \item local transition graph；
  \item heuristic middle-resolution views：
  \begin{itemize}
    \item diffusion residual；
    \item band-pass proxy；
    \item community-aware view。
  \end{itemize}
\end{itemize}

其中适用时分别比较 raw 与 purified 版本。

\subsubsection*{主要结论}

第一轮里最有价值的 middle-resolution views 来自 purified heuristic views：

\begin{itemize}
  \item Industrial：最好的 middle view 是 \texttt{mid\_band\_pass\_purified}，\texttt{same\_l2 = 0.2747}
  \item Office：最好的 middle view 是 \texttt{mid\_diffusion\_purified}，\texttt{same\_l2 = 0.2381}
\end{itemize}

这一轮的意义是明确了：

\begin{quote}
middle-resolution collaborative structure 值得被当成一个一等设计对象，而不是顺手派生出来的附属信号。
\end{quote}

\subsubsection*{说明了什么}

这轮结果支持下面这个解释：

\begin{quote}
对深层 leaf ambiguity 最有用的协同信息，既不是纯 global，也不是纯 local。中尺度视图是必要的。
\end{quote}

\subsection{阶段 2：论文模块移植 Probe（2026-04-09）}

\subsubsection*{做了什么}

第二轮 probe 依然保持为独立实验模块，但移植了两类更接近相关工作的思想：

\begin{itemize}
  \item \textbf{PRISM 风格的 semantic-anchor purification}
  \item \textbf{GSPRec / FaGSP 风格的频域 middle-resolution graph views}
\end{itemize}

这一轮仍然没有改 SID 训练本体，而是在同样的 top-1 error probe 框架下测试更强的 graph carrier。

\subsubsection*{主要结果}

\begin{longtable}{p{0.26\linewidth}p{0.16\linewidth}p{0.16\linewidth}p{0.24\linewidth}}
\toprule
视图类型 & Industrial 最好 \texttt{same\_l2} & Office 最好 \texttt{same\_l2} & 说明 \\
\midrule
第一版 heuristic middle-view & 0.2747 & 0.2381 & 上一轮最强 purified proxy \\
移植后的 spectral middle-view & 0.5401 & 0.7619 & 都来自 \texttt{fagsp\_mid\_base} \\
\bottomrule
\end{longtable}

更具体地说：

\begin{itemize}
  \item Industrial：
  \begin{itemize}
    \item 上一轮最强中尺度视图：\texttt{mid\_band\_pass\_purified = 0.2747}
    \item 当前最强移植视图：\texttt{fagsp\_mid\_base = 0.5401}
    \item 第二强移植视图：\texttt{gsprec\_mid\_prism = 0.5247}
  \end{itemize}
  \item Office：
  \begin{itemize}
    \item 上一轮最强中尺度视图：\texttt{mid\_diffusion\_purified = 0.2381}
    \item 当前最强移植视图：\texttt{fagsp\_mid\_base = 0.7619}
    \item 第二强移植视图：\texttt{gsprec\_mid\_prism = 0.6429}
  \end{itemize}
\end{itemize}

\subsubsection*{说明了什么}

这一轮是目前为止最强的一次正信号：

\begin{quote}
当前的 \texttt{G\_mid} 很可能应该被设计为一个真正的 graph-spectral middle-resolution collaborative view，而不是只依赖 heuristic diffusion / band-pass proxy。
\end{quote}

同时，这轮结果也说明：

\begin{quote}
semantic-anchor purification 本身是有帮助的，但真正的大幅增益主要来自更强的中尺度结构表达，而不只是 anchor-only denoising。
\end{quote}

\subsection{阶段 3：训练脚手架校准（过渡阶段）}

在进入正式训练验证之前，我们做过几轮训练脚手架和配置校准，用来确认两件事：

\begin{itemize}
  \item 独立实验分支可以在不破坏 baseline 主链的前提下稳定运行；
  \item 真正有意义的方法比较必须建立在与 MiniOneRec 上游一致的训练制度上。
\end{itemize}

这一阶段的详细过程不再作为当前主线证据保留。对当前研究真正有价值的结论只有一条：

\begin{quote}
在做 graph-aware SID 对比之前，必须先解决 baseline provenance 与训练制度对齐问题。
\end{quote}

\subsection{阶段 4：SID provenance 追踪与上游风格复现（2026-04-09）}

\subsubsection*{做了什么}

为了确认当前正式 Industrial SID 的真实来源，我们专门做了两件事：

\begin{itemize}
  \item 对比本地迁移版与上游 MiniOneRec 官方仓库中的 \texttt{rqvae.py}、\texttt{trainer.py}、\texttt{generate\_indices.py} 核心逻辑；
  \item 在本地主线代码上，按上游官方训练超参数重新跑一遍 Industrial 的 \texttt{RQ-VAE -> sid-generate}。
\end{itemize}

\subsubsection*{主要结果}

对比上游后发现：

\begin{itemize}
  \item 核心 \texttt{sid-train / sid-generate} 代码逻辑没有被迁移改坏；
  \item 真正的关键差异在于训练制度：
  \begin{itemize}
    \item 上游官方：\texttt{epochs = 10000, batch\_size = 20480}
    \item 当前本地默认：\texttt{epochs = 10, batch\_size = 256}
  \end{itemize}
\end{itemize}

随后，按上游风格重跑 Industrial：

\begin{itemize}
  \item \texttt{sid-train} 最佳 collision 降到 \(\approx 0.0993\)；
  \item 继续跑 \texttt{sid-generate} 后，最终 \texttt{index.json} collision 变为 \(\approx 0.0043407488\)；
  \item 这个值与仓库中当前正式 Industrial index 的 collision 完全一致。
\end{itemize}

\subsubsection*{说明了什么}

这一轮非常关键，因为它修正了我们对基线系统的理解：

\begin{quote}
当前正式 Industrial SID 是可以被当前主线代码复现出来的，问题不在于迁移时改坏了主逻辑，而主要在于本地默认训练超参数偏离了上游 MiniOneRec。
\end{quote}

这也意味着，后续所有 graph-aware 实验如果还想保持说服力，就必须在 \textbf{upstream-aligned} 训练制度下进行。

\subsection{阶段 6：Upstream-aligned MGR-SID v1 训练与生成（2026-04-09 / 2026-04-10）}

\subsubsection*{做了什么}

在确认基线 provenance 后，我们把 \texttt{MGR-SID v1} 的训练实验也切换到了与上游对齐的训练制度：

\begin{itemize}
  \item \texttt{epochs = 10000}
  \item \texttt{batch\_size = 20480}
  \item Industrial only
  \item 三组对照：
  \begin{itemize}
    \item baseline
    \item uniform graph regularization
    \item hierarchy-aware graph regularization
  \end{itemize}
\end{itemize}

训练结束后，我们没有停留在 \texttt{sid-train} 指标，而是对每个 best checkpoint 单独跑了实验版 generate，比较最终 \texttt{index.json} collision。

\subsubsection*{主要结果}

\paragraph{Generate-stage final collision}

\begin{itemize}
  \item baseline：\(\approx 0.0035268584\)
  \item uniform\_reg：\(\approx 0.0059685296\)
  \item hierarchy\_reg：\(\approx 0.0032555616\)
\end{itemize}

其中最关键的是：

\begin{itemize}
  \item \texttt{hierarchy\_reg} 成为三者里最终最好的 SID；
  \item baseline 也比当前仓库里原有正式 Industrial index 的 \(\approx 0.0043407488\) 更低；
  \item 说明这轮 upstream-aligned 训练本身已经把语义 baseline 推到了更健康的 regime。
\end{itemize}

\subsubsection*{说明了什么}

这是当前研究里最重要的新转折之一：

\begin{quote}
当前最重要的判断标准应该是 final generated SID，而不是单独盯住 raw \texttt{sid-train} collision；在这个更合理的判据下，当前这版 hierarchy-aware graph regularization 已经给出了第一轮清晰正信号。
\end{quote}

更具体地说，这一轮至少说明了三件事：

\begin{itemize}
  \item \texttt{hierarchy-aware} 方向不是空想，它已经在最终 Industrial SID 上给出正结果；
  \item 后续评估应该优先围绕 \textbf{final generated SID} 展开，而不是再把全部判断压在 train-stage collision 上；
  \item 当前实验主线已经具备继续推进的依据，不再只是 probe 级别的希望信号。
\end{itemize}

\subsection{阶段 7：实验数据转换与第一轮 SFT + Evaluate（2026-04-10）}

\subsubsection*{做了什么}

在确认 final generated SID 上已经有正信号之后，我们先没有进入 RL，而是做了最小下游验证。具体分成两步：

\begin{itemize}
  \item 基于两套 Industrial tokenizer 结果，建立隔离的 \texttt{data\_experiment} 目录，保持与现有 \texttt{data/Amazon} 相同的结构，只替换：
  \begin{itemize}
    \item \texttt{history\_item\_sid}
    \item \texttt{item\_sid}
  \end{itemize}
  \item 然后对两套数据分别跑平行的 \texttt{SFT -> evaluate}：
  \begin{itemize}
    \item \texttt{mgr\_upstream\_baseline}
    \item \texttt{mgr\_upstream\_hierarchy}
  \end{itemize}
\end{itemize}

\subsubsection*{主要结果}

两条链最终都完整跑通。Industrial 上的关键指标如下：

\begin{itemize}
  \item baseline：
  \begin{itemize}
    \item \(\mathrm{NDCG}@1 = 0.06309\)
    \item \(\mathrm{NDCG}@3 = 0.07772\)
    \item \(\mathrm{NDCG}@10 = 0.09430\)
    \item \(\mathrm{HR}@1 = 0.06309\)
    \item \(\mathrm{HR}@3 = 0.08824\)
    \item \(\mathrm{HR}@10 = 0.13435\)
  \end{itemize}
  \item hierarchy：
  \begin{itemize}
    \item \(\mathrm{NDCG}@1 = 0.06265\)
    \item \(\mathrm{NDCG}@3 = 0.08025\)
    \item \(\mathrm{NDCG}@10 = 0.09360\)
    \item \(\mathrm{HR}@1 = 0.06265\)
    \item \(\mathrm{HR}@3 = 0.09287\)
    \item \(\mathrm{HR}@10 = 0.13038\)
  \end{itemize}
\end{itemize}

最直接的 delta 是：

\begin{itemize}
  \item \(\mathrm{NDCG}@3 = +0.00253\)
  \item \(\mathrm{HR}@3 = +0.00463\)
  \item \(\mathrm{NDCG}@5 / \mathrm{HR}@5\) 也有轻微提升
  \item 但 \(\mathrm{NDCG}@1 / \mathrm{HR}@1\) 和 \( @10+ \) 仍然弱于 baseline
\end{itemize}

\subsubsection*{说明了什么}

这一轮的意义不是“hierarchy 已经全面赢了”，而是更细的：

\begin{quote}
tokenizer 侧的结构收益已经可以部分传到下游，但目前主要体现为短程排序增益，而不是全面的 end-to-end 优势。
\end{quote}

这说明两件事：

\begin{itemize}
  \item 当前方向不是只在 tokenizer 原地自嗨，它确实会影响下游行为；
  \item 但当前 tokenizer-to-SFT 的传递还不够理想，仍然存在一部分收益在下游被抵消。
\end{itemize}

\subsection{阶段 8：SFT 历史对比与 Evaluate 错误分布分析（2026-04-10）}

\subsubsection*{做了什么}

在拿到第一轮 SFT 结果后，我们又补了两类分析：

\begin{itemize}
  \item 与项目内历史 Industrial SFT 记录做主指标对比；
  \item 对 baseline 与 hierarchy 的最终 evaluate 输出做 SID-aware 错误分布诊断。
\end{itemize}

\subsubsection*{主要结果}

\paragraph{与历史 CSV 的对比}

结果显示，当前两条新实验都还没有超过历史最强 Industrial SFT 设定：

\begin{itemize}
  \item 历史最强：\texttt{title\_history2sid\_off + desc\_align\_p05}
  \item 当前 hierarchy：只在 \(\mathrm{NDCG}@3\) 上略高于“最接近当前设定”的历史 baseline，并在 \(\mathrm{HR}@3\) 上持平
  \item 但在 \( @10+ \) 指标上，当前 baseline 与 hierarchy 都还偏弱
\end{itemize}

\paragraph{Evaluate 错误分布}

这轮分析给出了目前最重要的机制性证据。核心数字包括：

\begin{itemize}
  \item top-1 error same-\(l_1\) rate：\(0.1815 \rightarrow 0.1236\)
  \item top-1 error same-\(l_2\) rate：\(0.0525 \rightarrow 0.0370\)
  \item crowded targets（target \(l_2\) fanout \(\ge 4\)）上的 top-1 hit：\(0.0475 \rightarrow 0.0521\)
  \item baseline same-\(l_2\) errors 的恢复率：\(0.0538\)
\end{itemize}

逐样本对比还显示：

\begin{itemize}
  \item hierarchy 修复了 \(63\) 个 baseline top-1 miss；
  \item 但也打坏了 \(65\) 个 baseline 原本正确的 top-1 hit；
  \item fixed cases 的平均 target \(l_2\) fanout 高达 \(7.32\)，说明它们大多是更拥挤、更难的局部歧义样本；
  \item broken cases 则往往是 baseline 本来就已经进入正确局部子树的样本。
\end{itemize}

\subsubsection*{说明了什么}

这一轮把“为什么 hierarchy 只在短程指标上更好”解释清楚了：

\begin{quote}
hierarchy-aware SID 的确在修我们关心的 crowded local ambiguity，但它当前也会打掉一部分 baseline 原本已经正确的局部 routing。
\end{quote}

也就是说，当前瓶颈已经不再是“tokenizer 方向对不对”，而更像是：

\begin{quote}
如何让 tokenizer 侧的局部歧义收益，在 SFT 阶段被更完整地保留下来，而不是同时损伤 coarse/local retention。
\end{quote}

\subsection{阶段 9：Ambiguity-aware tokenizer v2（2026-04-11）}

\subsubsection*{做了什么}

在看清 v1 的长处与副作用之后，我们没有继续做后验 patch，而是回到 tokenizer 训练本体，提出并实现了 \texttt{MGR-SID v2}。这一版的核心变化有两点：

\begin{itemize}
  \item 用 \textbf{offline ambiguity prior} 去调节 graph regularization 强度，而不是对所有 item 一刀切；
  \item 用 \textbf{semantic-structure retention} 保护训练前就可见的原始语义几何，避免图正则在低歧义区域过度改写 semantic neighborhood。
\end{itemize}

在进入训练前，我们先做了最小 proxy sanity：

\begin{itemize}
  \item \texttt{R001}：离线 combined ambiguity prior，由 semantic density、semantic-collaborative disagreement 和 graph competition strength 组成；
  \item \texttt{R002}：在 \texttt{R001} 基础上加入当前量化过程里的 online uncertainty。
\end{itemize}

\subsubsection*{主要结果}

\paragraph{Proxy sanity}

\begin{itemize}
  \item \texttt{R001}：\(\mathrm{AUC} = 0.7187\)
  \item hard-item base rate：\(0.2580\)
  \item proxy top \(10\%\) 中的 hard-item 比例：\(0.6141\)
  \item \texttt{R002}：\(\mathrm{AUC} = 0.5859\)
\end{itemize}

因此，当前 first v2 run 只采用 \texttt{R001} 的 offline combined proxy，而不采用当前这版 online uncertainty。

\paragraph{Tokenizer 训练与生成}

Industrial 上，\texttt{v2 offline\_combined} 的结果为：

\begin{itemize}
  \item best train collision：\(\approx 0.1226261530\)
  \item final generated collision：\(\approx 0.0035268584\)
  \item max conflict：\(2\)
\end{itemize}

如果只看 final collision，\texttt{v2} 打平了 internal control baseline，但没有超过 \texttt{v1 hierarchy}。然而结构诊断却更强：

\begin{itemize}
  \item 相比 internal control baseline，mean target \(l_2\) leaf count：\(4.7999 \rightarrow 4.3422\)

即使与 \texttt{v1 hierarchy} 相比，\texttt{v2} 的局部结构仍然更干净：

\begin{itemize}

\end{itemize}

\subsubsection*{说明了什么}

这一阶段最重要的更新是：

\begin{quote}
\texttt{v2} 不是“collision 更低”的 tokenizer，而是“局部结构更干净”的 tokenizer。当前真正卡住它的，不像是 ambiguity-aware 思路本身，而更像是 train-to-generate 接口还没有把这种结构收益完整兑现成 final collision。
\end{quote}

换句话说，\texttt{v2} 已经把“hard case 强化 graph supervision、easy case 保护 semantic structure”这条思路，落实成了可见的 tokenizer 结构收益。

因此，当前最可信的 downstream interpretation 已经从“\texttt{v2} 还要去 strongest recipe 里验证”更新为：

\texttt{v2} 已经完成了 strongest recipe 的拆因子验证，并且当前最优下游 recipe 是 \texttt{title\_history2sid\_on + desc\_align\_p05}。它与 strongest original MiniOneRec SFT 的差距已经很小，剩余差距主要表现为中段 beam retention，而不是头部排序或 same-prefix disambiguation 能力不足。

\subsection{阶段 12：Retention-targeted tokenizer refinement 第一轮结果（2026-04-13，已完成首轮筛选）}

\subsubsection*{做了什么}

在完成 \texttt{v2\_on\_p05 -> RL} 的 end-to-end 验证后，我们没有立刻重新设计 graph bank，也没有直接扩展更复杂的 gate / joint training，而是把当前主问题收束为：

\begin{quote}
如何在不重新打开大设计空间的前提下，专门补当前剩余的 \texttt{top5/top10} mid-beam retention gap？
\end{quote}

围绕这个目标，我们完成了 stage-2 第一批 tokenizer 微调实验：

\begin{itemize}
  \item \texttt{R202a}：\texttt{stop-gradient} hierarchy isolation
  \item \texttt{R202b}：\texttt{stop-gradient} hierarchy isolation + level-1 compensation
  \item \texttt{R205}：\texttt{R202a} 基础上的 batch-local semantic neighborhood KL retention
  \item \texttt{R208}：\texttt{R202a -> data conversion -> SFT -> evaluate}
\end{itemize}

这一轮实验的共同原则是：

\begin{itemize}
  \item graph bank 固定不动；
  \item ambiguity prior 固定为 current offline combined proxy；
  \item 下游固定 recipe 为 \texttt{title\_history2sid\_on + desc\_align\_p05}；
  \item 只测试最小、最可诊断的 retention-targeted tokenizer 改动。
\end{itemize}

\subsubsection*{主要结果}

\paragraph{Block 2：Stop-gradient hierarchy isolation}

\begin{itemize}

\texttt{stop-gradient} hierarchy isolation 确实触及了一个真实瓶颈：跨层梯度干扰；但 current stage-2 的 tokenizer 微调还没有把这种结构收益稳定兑现成更强的下游结果。当前最强主线仍然是 \texttt{v2\_on\_p05 -> RL}，而不是任何已完成的 stage-2 分支。
\end{quote}

\section{当前证据的整体解释}

把目前的证据串起来，可以得到一个更清楚的图景：

\begin{enumerate}
  \item 当前 semantic SID 足以提供较强的 coarse routing，而真正持续暴露出来的困难集中在 local leaf-level discrimination；
  \item graph-structured collaborative signal 对这个瓶颈是有帮助的，而且其中最强的载体是 \textbf{spectral middle-resolution collaborative graph view}；
  \item 如果图约束均匀地作用在所有 item 上，确实会出现过度修正，因此真正需要的不是“更强 graph”，而是 ambiguity-aware 的 graph supervision；
  \item 当前仓库默认 \texttt{sid-train} 配置不能代表正式 MiniOneRec baseline，所有方法比较都必须建立在 upstream-aligned tokenizer regime 上；
  \item \texttt{v1 hierarchy-aware} 已经证明：graph regularization 能在 final generated SID 和 crowded local ambiguity 上给出真实收益，但这份收益在下游只部分保留；
  \item \texttt{v2 ambiguity-aware tokenizer} 进一步证明：如果 graph supervision 只在高歧义区域更强、在低歧义区域更多保留 semantic structure，最终 SID 的局部层级结构可以明显更干净；
  \item 当前 \texttt{v2} 在原版 MiniOneRec 上给出的下游正信号是 recipe-sensitive 的：\texttt{title\_history2sid\_on + desc\_align\_p05} 已经成为 \texttt{v2} 的最佳下游 recipe；
  \item strongest original recipe 与 \texttt{v2} 的主冲突并不来自 \texttt{desc\_align\_p05}，而主要来自 \texttt{title\_history2sid\_off}；
  \item 当前 \texttt{v2\_on\_p05} 与 strongest original MiniOneRec SFT 已经非常接近，剩余差距主要表现为中段 beam retention，而不是 top-1 或 same-prefix disambiguation 的能力不足。
  \item stage-2 第一轮结果表明：\texttt{R202a} 的 stop-gradient 能改善 retention-oriented tokenizer structure，但 \texttt{R205} 这版 semantic retention KL 和 \texttt{R202b-r075} 这类 level-1 compensation 都更像“collision 更好但结构更差”的 tradeoff 分支；
  \item 因此，当前的关键事实已经从“是否需要 stage-2 微调”推进到“为什么 tokenizer 侧的结构收益没有稳定保留到下游 \texttt{SFT/evaluate}”。
\end{enumerate}

\section{当前最佳工作假设}

当前最可信的工作假设是：

\begin{quote}
MiniOneRec 应该继续保留 semantic tokenizer 作为 backbone，同时引入 \textbf{ambiguity-aware graph supervision + semantic-structure retention}。其中 middle-resolution spectral collaborative graph 仍然是最关键的协同载体，而 downstream 最优 recipe 当前更像是 \texttt{title\_history2sid\_on + desc\_align\_p05}。在这条 recipe 上，\texttt{v2} 已经把主要问题压缩成一个中段 beam retention gap；但 stage-2 第一轮说明，这个 gap 还不能靠当前版本的 stop-gradient 或 semantic-retention KL 直接补平。因此当前最强 end-to-end 主线仍然是 \texttt{v2\_on\_p05 -> RL}，而 stage-2 更像是在暴露“结构收益为何没有下游兑现”的接口问题。
\end{quote}

当前最强的 \texttt{G\_mid} 候选仍然是：

\begin{itemize}
  \item 主候选：\texttt{fagsp\_mid\_base}
  \item 备选：\texttt{gsprec\_mid\_prism}
\end{itemize}

当前最合理的 baseline 分层也更清楚了：

\begin{itemize}
  \item 主 baseline：原版 MiniOneRec 的最强 SFT / RL 结果；
  \item recipe-aligned baseline：\texttt{title\_history2sid\_on + desc\_align\_off} 的原版 MiniOneRec；
  \item internal control：\texttt{mgr\_upstream\_baseline} 与 \texttt{mgr\_upstream\_hierarchy}，用于机制分析与消融，而不是主表锚点；
  \item 当前主方法候选：\texttt{v2\_on\_p05}（tokenizer 为 \texttt{v2 offline\_combined}，下游 recipe 为 \texttt{title\_history2sid\_on + desc\_align\_p05}）。
\end{itemize}

\section{当前开放问题}

即使有了新一轮 probe，下面这些问题仍然没有完全解决：

\begin{enumerate}
  \item 当前 \texttt{v2\_on\_p05} 相对 strongest original MiniOneRec SFT 的中段 beam retention gap，究竟来自下游训练目标、解码行为，还是更深层的 representation transfer 问题？
  \item \texttt{v2} 更干净的 local hierarchy，为什么没有通过 \texttt{sid-generate} 继续转化成更低的 final collision？
  \item 为什么 \texttt{R202a} 这类 tokenizer-side 的 clean structural gain，到了 \texttt{R208} 的 \texttt{SFT/evaluate} 并没有继续转化成更强的 \(\mathrm{NDCG}@10 / \mathrm{HR}@10\)？
  \item 当前 semantic-structure retention 的更合理最小实现到底是什么？第一版 batch-local neighborhood KL 已经给出负结果，那么下一步应该往更弱的 KL、pairwise ranking，还是其他邻域保持形式收缩？
  \item 当前 offline ambiguity prior 是否已经足够，还是需要在不破坏 clean logic 的前提下补一版更稳的 online uncertainty？
  \item 如果 tokenizer 微调在 SFT 上只给出很小增益，这个增益是否能够在第二个 seed 上稳定复现？
  \item 什么时候再把 internal control、Office、完整消融和 published baselines 拉回主线，避免过早扩展。
\end{enumerate}

\section{下一步行动}
